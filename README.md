# ISOLATE / 私藏物语

运行在 **GitHub Pages** 的私人影视、人物与角色收藏册。乙女游戏风格的晨光玫瑰 / 月夜雾紫 / 樱粉校园三套配色，大字号与个人收藏边界保持兼容。

https://z2vn7g8nhp-beep.github.io/isolate-love-movie/

## 独立的 GitHub 图片数据

当前项目自己维护 `photo-data/`，GitHub Actions 每小时读取公开片目清单，抓取 IMDb、豆瓣与 Pinterest 的图片元数据，再发布为静态 JSON。网页的「从三站图库读取更多」直接读取下一批（每站最多 12 张），不要求复制链接，也不需要常驻后台。图片优先使用有界的静态预览，其他文件来自原站 CDN，本机缓存沿用。

数据流：相册／新增收藏 → 独立的公开编号队列 → GitHub Actions → `photo-data/subjects/<IMDb ID>.json` → 相册。已有条目仍由每小时任务补充。

- 数据目录只有公开标识、公开图片地址、来源、检索方式及更新时间。收藏、评分、笔记、专属称呼不会上传。首页仍只展示亲自收藏的条目。
- 豆瓣使用无需登录的公开相册数据，核对相册所属条目；IMDb / Pinterest 的原站请求受限时，尝试公开页面或图片搜索索引。索引结果要求原站页面与原站图片 CDN 对应，并匹配当前标题，分别标为「搜索索引」。Pinterest 可从公开 Pin 和名称匹配的主题图板补充图片。
- 每站独立记录状态。失败保留旧图片，不用其他来源冒充；网页显示数据更新时间。受限来源和没有索引的条目可能暂时没有新增图片。
- 主动申请的条目会保存豆瓣公开预览，避免原站防盗链导致「有图片地址却看不到图」。每条目最多 48 张，单张最长 960 像素、180 KB，保存为 WebP；原始来源链接保留。静态预览同样进入本机图片缓存，可放大、收藏和设为封面。此处使用相册匿名提供的公开图片与正常来源标头，不使用登录或验证绕过。已有静态预览不反复下载或重编码。
- **更多按钮读取已抓取数据，不能无授权地即时触发 GitHub 工作流。** 后台按小时轮询公开清单，GitHub 调度可能延迟。
- 新增收藏时自动检查图库，未建库则在后台提交一个公开 IMDb 编号；相册里的「更多」读完现有图片后，也可直接排队补图。无需跳转、表单或 GitHub 访问令牌。进度留在相册里，完成后自动重新读取图片。旧的 GitHub Issue 工作流仅保留兼容性，界面不再提供该入口。
- 独立队列的应用数据只接受一个公开 `id`；匿名会话用于鉴别队列请求，拒绝其他字段。不会接收收藏列表、私人称呼、评分或笔记。角色只使用关联的作品或演员编号。编号及采集后的公开图片仍会进入公开数据目录。
- 队列给浏览器分配有期限、仅能使用补图队列的匿名会话，保存在本机独立存储项中。它不是 GitHub 凭据，不进入藏柜备份。来源校验、单设备／全局限额、同一编号去重以及队列状态查询均在接口处理。采集入口只接受此仓库 `main` 上指定工作流的 GitHub OIDC 短期签名身份，网页与接口均无需保存 GitHub 令牌。
- 直连通道使用简单 CORS POST：`text/plain` 请求体包含公开编号和匿名会话，不发送自定义授权请求头，不需要预检，也不把会话放进 URL。旧授权头协议继续兼容。
- 主屏幕版优先使用站内嵌入的同源通道；其他浏览器直连失败后自动切换。服务只允许原 GitHub 网页作为父页面，双方验证来源和消息窗口，仅接受固定补图／状态操作及公开编号。匿名会话通过浏览器消息传递并保存在本机，不放进 URL；不需要 Cookie、登录、跳转或放宽采集权限。内嵌页面的 CSP 限制脚本与网络来源，服务内请求使用同源来源策略。挂起的通道超时后可重新建立。
- 提交前先在本机保留请求。连接失败时显示「待发送」，恢复网络、返回应用或重开主屏幕版后自动重试；按 3 秒、15 秒、1 分钟、3 分钟退避，已有图不会被清空。旧版 `Load failed` 和中断提交会自动恢复。若 GitHub 图库已更新，则直接读取静态图片，不再等待接口连接。真实已收到的请求才显示后台排队／采集中。
- `.github/workflows/photo-queue.yml` 计划每 5 分钟检查一次队列，每批最多 8 个公开条目；空队列不安装采集器、不构建、不发布。GitHub 调度可能延迟，因此排队不等于即时采集。独立接口已获明确授权开放，供原网页匿名提交公开编号；网站本身继续托管在原 GitHub Pages 地址。
- 相册显示提交时间、实际已等待时长、前方条目数，以及排队、采集、发布、完成四个阶段。采集器逐站回报 IMDb、豆瓣、Pinterest 的结果，完成后显示去重后的图库新增量；0 张也是明确的完成结果。打开应用时每 20 秒检查进度；调度延迟、进度连接中断及超过 15 分钟没有采集回报分别提示，不承诺无法保证的完成时间。发布成功后还会核对静态图库版本，旧缓存不会被当作新图库。
- 当前 GitHub 连接不具备创建仓库的权限，所以先使用 ISOLATE 本项目内的独立数据目录。后续可拆到单独的数据仓库，调整发布路径及 `PHOTO_DATA_BASE` 即可。不接入或复用其他项目。

`server/photo-api.mjs` 提供独立来源读取和本地开发适配；`scripts/photo-crawl.mjs` 运行抓取任务；`scripts/photo-index.mjs` 发现并验证公开图片索引；`scripts/photo-request.mjs` 只核对并登记公开 IMDb 标识；`public/photo-client.js` 读取静态数据；旧请求链接仅保留兼容性。接口契约测试与实际 GitHub Runner 抓取验证分开记录，不把任务结束视为每站抓取成功。

`server/photo-queue.mjs` 是独立队列 Worker 的同源代码，使用 Sites 新服务的 R2 存储；`public/photo-queue-client.js` 只发送公开编号；`scripts/photo-queue.mjs` 供当前仓库的采集工作流取队列、核对公开条目及反馈发布状态。与其他仓库、旧服务无关联。

## 收藏由你决定

- 首页和各个分柜只展示你亲自收入的藏品。没有默认推荐片单、未关注人物或预填角色。
- 搜索结果仅供选择；打开预览、查看演职或刷新辅助资料不会自动入藏。
- 已有的已看 / 想看 / 关注、偏爱、评分、笔记视为原有收藏，升级后保留。
- 明确「收入藏柜」或填写自己的记录后才进入藏柜。可以移出并撤销，移出时保留原笔记和编号。

## 你的编目与藏印

每件藏品有固定编号，排序和筛选不会更改它。支持个人标签、评分、观看日期、笔记、偏爱藏印、邮票式陈列和列表视图。藏柜名称与藏印署名可以自定义，封面只能从自己的藏品中选。

电影 / 剧集、人物、角色之间的关联，只在「我的藏品关联」中呈现已经入藏的条目。角色可以从作品或人物内部建立，自动关联已入藏的所属作品与饰演者。

默认 18px 阅读字号，右上角 Aa 可调大；手机也可选择大号或特大。偏好会保留。

## 新增的个人功能

- **映像相册**：按选定实体精确检索图片；支持大图、左右切换、收藏相片、自选私藏封面。导航中的「相册」只显示你亲自收藏的图片。
- **专属称呼与摘句**：不会改写来源数据，只在自己的收藏册中展示。
- **重温手记**：亲自记录每次的日期、心情和文字，支持移除撤销。
- **相遇日历**：只列出已收藏人物的已核对生日，以及本机有真实入藏时间的纪念日。只在页面内显示，不声称提供系统推送。
- **图像档案**：默认进入影像与演职 / 人物与作品页，另有全部图片、我的手记、详细资料、私藏关联四个页签。

晨光玫瑰、月夜雾紫和樱粉校园可在 Aa 设置中切换，主题、字号和现有记录都会保留。

## 藏品内部

首屏以作品大幅背景 / 人物肖像、影像横卷和海报墙呈现，个人评分与入藏状态固定在封面。笔记与编辑表单放在「我的手记」。辅助档案通过 Wikidata P345 与 IMDb ID 精确匹配后补充，能获取的字段才显示：

- 影视：上映 / 首播日期、片长、类型、制作国家、语言、集数、季数、系列、改编来源、摄影、剪辑、制片人与获奖记录。
- 人物：出生日期、出生地、国籍、职业、身高、使用语言、教育经历、获奖记录、已记录的代表作品。
- 影视的演职用肖像卡片呈现，Wikidata 有明确角色限定时补充角色名；剧集额外补充 TVmaze 中的演员 / 角色双肖像。只在同一作品下的完整姓名唯一匹配 Wikidata 已验证演职时继承 IMDb 人物标识，其余人物主动搜索再选择。
- 影人作品从 Wikidata 反向查询参演 / 导演记录，最多读取 100 个候选后逐条核对真实关系，按年份排列为海报墙，支持年份筛选与展开。来源可能不完整。
- 中文维基百科人物介绍 / 剧情优先，缺失时补充有明确作品标识关联的英文简介。每段保留来源链接。
- 演职与作品可打开预览，查看不会自动入藏；私藏过的条目在卡片上显示藏印。
- 角色关系由你编目，角色图像使用饰演者肖像并标注。

辅助资料按需读取并在本机缓存 6 小时，可以手动重新核对。数据源不完整时保留原资料，不填造未知字段或平台评分。

## 图片来源

IMDb 主图、MetaHub 的 IMDb 作品关联背景图、Wikidata 指定配图，以及 Wikimedia Commons 中明确 `depicts` 对应实体的照片（每次按 12 张继续查询，保留分页位置，已有图片不会被替换）。剧集通过 IMDb 标识精确匹配 TVmaze，读取海报、演员 / 角色肖像，以及首季最多 16 张对应单集的图片（继续找图可按单集 / 季追加）；电影由 Cinemeta 的相同 IMDb 标识补充最多 5 张 YouTube 预告封面。海报、肖像、背景图、剧照与预告封面分别标注，不能获取的受限剧照不声称已抓取。单条目相册最多保留 240 张已选来源图片。图片地址按文件去重，避免不同分辨率重复入册。人物的多图检索不通过泛关键词猜测其他人物；角色相册在有明确关联时使用已关联饰演者的肖像，并标注其性质。

Commons 图片保留可取得的作者、授权和原始说明页，图片缩略图支持 upload.wikimedia.org / thumb.wikimedia.org。缺失字段不编造，来源失败时保留已有相册。备份中的相片与封面保存 URL。网页另有独立的本机图片缓存，优先读取缓存，应用升级不删除它；普通可读取图片最多缓存 120 张，不支持跨域读取的图片最多 12 张，超过容量逐步淘汰旧图。浏览器可能因存储压力清理缓存，清理网站数据也会清除缓存。缩略图用于列表，只有打开大图时读取原尺寸；外部图片请求最多同时进行 4 个，补全 IMDb 肖像最多同时 2 个。

## 继续找图与选图

- 「继续寻找更多」沿 Commons 分页和 TVmaze 单集 / 季游标追加可用图片，保留已有相册；没有新图时明确提示。相册默认显示 12 张，可继续分批展开。
- IMDb、豆瓣与 Pinterest 有原站选图入口，查询只围绕当前档案；直接批量读取 IMDb / 豆瓣受访问与跨域限制，不声称已接通它们的相册 API。
- 粘贴公开 Pinterest Pin 或图板链接，通过官方公开 Widgets 入口读取图片；图板图片每批 12 张供选择，主动确认的图片才入藏。也可粘贴 IMDb、豆瓣、Pinterest 等受支持图片地址，保留来源；不读取登录态或私密图板。
- 演员与角色有各自的图片时，角色大图、演员小头像；点角色放大，点演员进入人物档案。没有角色图时明确标注演员肖像。手机角色卡改为两列，关闭栏与页签分别固定。
- 缓存命中和页签切换保留现有图像节点；补充相册时只更新图片区域。档案打开时延后绘制背后的藏柜，减少重复图片解码。资料与图片索引缓存有数量与体积上限，避免占满个人记录的存储空间。

## 数据与存储

IMDb 是主索引。浏览器使用官方 `sg.media-imdb.com/suggests/` JSONP 搜索入口，解决静态站点的 CORS 限制。Wikidata 使用带 `origin=*` 的公开 MediaWiki API。TVmaze、Cinemeta 与维基百科作为档案图文辅助来源，访问失败时不影响个人记录；档案图文缓存 6 小时，图片来源查询缓存 24 小时，并可手动重新核对 / 寻找更多图片。豆瓣有已验证标识时直达，否则提供搜索入口。

「更新我的藏品」只请求已经入藏的 IMDb 条目。仓库中的公开目录仅供检索与旧记录元数据补全，不作为默认展示内容；GitHub Actions 每小时尝试更新这个辅助索引，定时任务可能被 GitHub 延迟或暂停。

个人数据保存在**当前浏览器 localStorage**，不上传到公开仓库。JSON 导出包含个人记录、固定编号、标签、专属称呼、摘句、重温手记、相册 URL、藏柜名称、主题、署名与封面选择。旧版 JSON 可以导入，记录按修改时间合并，当前藏品编号优先保留。跨设备使用请导出 / 导入；清理网站数据会删除本机记录。

作品、海报、肖像版权归原权利人。IMDb / Wikidata 的访问状况和数据完整性会影响可展示的补充字段。

## GitHub Pages 与开发

仓库 Settings → Pages → Source 选择 GitHub Actions。工作流 `.github/workflows/pages.yml` 在推送 main、手动运行和每小时时执行。构建会对 UI 资源生成内容版本，并更新离线应用缓存。

Node.js 22+，无安装依赖。

```sh
npm start       # http://127.0.0.1:3000
npm test        # 收藏边界、编号、兼容性、数据适配检查
npm run build   # 生成 dist/
npm run refresh # 刷新辅助公开索引，需要网络
```

`public/collection.js` 管理入藏边界、编号与旧记录兼容；`public/data-client.js` 管理 IMDb / Wikidata；`public/visual-data.js` 管理作品年表、演员 / 角色图像与图文辅助来源；`public/image-tools.js` 管理缩略图、图片去重和 Pinterest 主动选图；`public/app.js` 管理藏柜和藏品档案界面。
